## 4. 主な指摘の詳細

### QF-001 無効化と削除の対象を自分の行に絞っていない(安全性・高)

- S4([usr-user-management.spec.ts:82-85](../../../tests/specs/usr/usr-user-management.spec.ts#L82-L85)): 検索の直後、絞り込みの結果を待たずに、ページ全体で description が「有効」のコンボボックス([UserListPage.ts:38](../../../tests/pages/UserListPage.ts#L38))を押す
- S5([:99-101](../../../tests/specs/usr/usr-user-management.spec.ts#L99-L101)): S4 の検索状態に暗黙に依存し、ページの先頭のセル([UserListPage.ts:41](../../../tests/pages/UserListPage.ts#L41))を選んで削除を確定する
- 一覧は非同期で読み込まれ、組込みユーザーは表示されない(KB SCR-0003)。環境には残留ユーザーが9件ある(作業20報告書 §6)。検索が効かない・遅れると、先頭は他のテストのユーザーか実データになる
- 行に絞る手段は KB にすでにある(SCR-0003「ユーザーの行」)。一方で UIT-0007・0008 の「コードでの扱い」が、ページ全体のロケータを標準の書き方として定着させている。**このままでは次のフローも同じ書き方を流用する**
- 手順側の原因: テストデータ規約の2(自データスコープ)が対象にしているのはアサーションと DB の検証だけで、**状態を変える操作の対象**を自データに絞る規定がない

### QF-002 「他のユーザーの行は表示されない」が確かめられていない(検出力・高)

段階ごとに追うと、弱化が2回起きている。

| 段階 | 記録 | 判別力 |
|---|---|---|
| scenarios.md | 期待結果「作成したユーザーの行が表示され、**他のユーザーの行は表示されない**」 | — |
| 作業10 | notes「絞り込み前からこのユーザーの1行しかなく、非表示は前後で差が出ない」。それでも `passed` | なし(R-JDG-2 に当たる) |
| 作業10 assertion_hint | 「テーブル本体の行数が 1」 | 対照データがあれば有効 |
| 作業20 | `userLink(userId).toHaveCount(1)` に置き換え | なし(ユーザーIDは一意なので常に成り立つ) |

検索がまったく絞り込まなくなる回帰が起きても、このステップは合格する。作業20だけで行数の検査に戻しても、対照データ(消えるべき別のユーザー)がシナリオにないため、判別力は環境の残留データ次第になる。**是正には作業10(シナリオへの対照データの追加と探索のし直し)が要る。**

### QF-003 作業20での弱化が、作業40に届く経路がない(検出力・高。手順)

- 作業20は S2 の弱化を報告書 §6「検証の代替」と §7-2 に正直に書いている。ただし DoD が SIG を求めるのは「逸脱」と「コード化不能」だけで、「検証の代替」は SIG にも status.yaml にもならなかった
- 検出力ガード指標はすべて scenarios.md と非決定値カタログから計算するので、コードでの弱化はどの指標にも現れない
- 結果として、**F-001 は green・ガード異常なし・done で閉じ、弱化は unreviewed の報告書の中にだけ残っている**
- ガード指標に項目を足すのは保護ブロック(IMPROVEMENT_GOVERNANCE)の変更になる。人間の判断(区分C)

### QF-004 グループ名とユーザーIDが同じ文字列(検出力・中)

[usr-group-management.spec.ts:34](../../../tests/specs/usr/usr-group-management.spec.ts#L34) で `userId = groupName` としている(記録どおり)。

- S3 の「ユーザーグループ列に作成グループが表示される」の検査([:70](../../../tests/specs/usr/usr-group-management.spec.ts#L70))は、その文字列のセルがページにあるかしか見ていない。同じ行のユーザーIDのセルも同じ文字列である
- S4([:83](../../../tests/specs/usr/usr-group-management.spec.ts#L83))も同じ
- 3回 green なので実際にはどちらか一方のセルにだけ一致しているはずだが、どちらに一致しているかは静的には決められない(確度 中)。DB の検査では区別できているので、取り逃すのは画面の層だけである
