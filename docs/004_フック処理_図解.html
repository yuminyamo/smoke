フック処理の図解 — 改善案(docs/94)の中でフックが何をするか

フックは、AIの外側でIDEが決まったタイミングに実行するスクリプトです。AIはフックを読み飛ばせず、止めることもできません。この資料では、フックがAIの処理のどこに入るかを示し、そのうえで docs/94 の改善案(進行役 pms・カード・記録する道具 pms act)と組み合わせたときの1枚のカードの流れを、実際の入出力の例とともに示します。

フックの正体
IDE が実行するコマンド。標準入力で JSON を受け取り、標準出力の JSON で返答する
できること
ツールの実行を拒否する・AIに文脈を足す・終了を差し止める
できないこと
AIの判断の中身を変える。フックは入口と出口で止めるだけ
位置づけ
早く止めるための補助。正しさは pms submit の検査で担保する

1. フックが入る場所

エージェントは「次の行動を決める → ツールを実行する → 結果を見る」を繰り返し、最後に応答を終えます。フックはこの繰り返しの継ぎ目で起動します。継ぎ目を通らずに先へ進む方法はAIにはありません。

フックとのやりとり

フックのスクリプトは、標準入力から JSON を受け取り、標準出力に JSON を書いて終了します。例として、AIが端末で playwright-cli を直接呼ぼうとしたときの PreToolUse を示します。

IDE → フック(標準入力)
{
  "hook_event_name": "PreToolUse",
  "tool_name": "<端末ツールの名前>",
  "tool_input": {
    "command": "playwright-cli -s=F003 click e6"
  },
  "tool_use_id": "…"
}
フック → IDE(標準出力)
{
  "hookSpecificOutput": {
    "hookEventName": "PreToolUse",
    "permissionDecision": "deny",
    "permissionDecisionReason":
      "画面操作は pms act で行う。例: pms act click e6 --intent \"…\""
  }
}

拒否の理由はAIに渡されます。AIはこの理由を読んで pms act で操作し直します。終了コード 2 で終わった場合は、標準エラーの内容がそのままAIに渡り、ツールの実行は止まります。端末ツールの tool_name の実際の値は環境によって異なるため、最初に、受け取った値を記録するだけのフックを置いて実際の名前を確かめます(5章)。

2. 現行と改善後

左は現在の作業10です。右は docs/94 の改善案にフックを加えたものです。違いは3点あります。誰が記録を書くか、会話がどこで切れるか、検査がいつ行われるかです。

3. カード1枚の流れ(状態の整備)

状態 S-PRINTER-REGISTERED を画面操作で作るカード C-0412 を例にします。調査票001で記録が抜けた場面と同じ種類の作業です。上から下へ時間が進みます。

フックと pms submit の分担。フック(5・6、17〜19)は逸脱をその場で押し戻し、時間と費用の無駄を減らします。記録が正しいことは pms submit の検査(13〜16)が保証します。フックが無効な環境(組織の設定で止められている、Kiro の IDE など)でも、記録は pms act を通らなければ残らず、記録のない提出は不合格になります。そのため正しさは変わりません。変わるのは、やり直しが増えることだけです。

4. 使うフックと設定例

改善案で使うフックは次の5つです。最初の2つ(PreToolUse と Stop/SubagentStop)が中心で、ほかは補助です。

フック起動するときこの改善案でさせること止められるか
PreToolUseAIがツールを実行する直前端末で playwright-cli を直接呼ぶ操作と、procedure/・skills への書き込みを拒否する。拒否の理由で正しい呼び方を示す止められる
Stop / SubagentStopAIが応答を終えようとするときpms status を実行し、未提出のカードがあれば decision: block で続けさせる。人間の判断待ち(STOP)なら許可する止められる
PostToolUseツールの実行の直後pms act の結果が安定でないロケータなら警告を足す。毎回、現在のカードIDを1行添える(要約の後でも見失わないため)文脈を足す
SessionStart / SubagentStart会話・サブエージェントの開始pms next の結果(現在地)を最初の文脈に入れる文脈を足す
PreCompact会話が要約される直前現在のカードIDと再開のコマンドを状態ファイルに書く(記録を残すため。AIに文脈は足せない)書き出すだけ

設定ファイル(VS Code + Copilot)

フックの定義は .github/hooks/ に置きます。Windows の端末で動かすときのコマンドは windows 欄で別に指定できます。

// .github/hooks/pms.json
{
  "hooks": {
    "PreToolUse":   [{ "type": "command", "command": "node tools/hooks/guard.mjs",      "timeout": 10 }],
    "PostToolUse":  [{ "type": "command", "command": "node tools/hooks/after-tool.mjs", "timeout": 10 }],
    "Stop":         [{ "type": "command", "command": "node tools/hooks/stop-gate.mjs",  "timeout": 15 }],
    "SubagentStop": [{ "type": "command", "command": "node tools/hooks/stop-gate.mjs",  "timeout": 15 }],
    "PreCompact":   [{ "type": "command", "command": "node tools/hooks/pre-compact.mjs" }]
  }
}

終了を差し止めるフック(stop-gate.mjs の要点)

// 標準入力: { "hook_event_name": "SubagentStop", "stop_hook_active": false, ... }
const input = JSON.parse(await readStdin());
// 一度差し止めた直後の再停止は通す(無限ループを避ける。差し止めのたびにAIの利用枠を使う)
if (input.stop_hook_active) process.exit(0);

const st = JSON.parse(execSync("node tools/pms/pms.mjs status --json"));
if (st.waiting_for_human) process.exit(0);           // 人間の判断待ちは止まってよい
if (st.current_card && !st.current_card.submitted) {
  console.log(JSON.stringify({
    decision: "block",
    reason: `カード ${st.current_card.id} が未提出。pms submit を実行してから終える`
  }));
}

stop_hook_active を確かめずに差し止め続けると、AIが同じ失敗を繰り返したときに止まらなくなります。2回目は通し、未提出のまま止まったことは pms status の状態として残し、次の pms next で同じカードを出し直します。

6. Kiro との違い

Kiro にもフックはありますが、できることが Copilot より少ないです。特に IDE 版では、フックのスクリプトが「どのツールが、どの引数で呼ばれたか」を受け取れません。

やりたいことVS Code + CopilotKiro IDEKiro CLI(v3)
playwright-cli の直接呼びを拒否できるできない Pre Tool Use で止めることはできるが、コマンドのスクリプトにはツール名と引数が渡らない(Issue #7500、2026-04 から未解決)。shell の分類ごと全部を止めるか、AIに判断させるフックになるできる PreToolUse を終了コード 2 で止める。入力は標準入力の JSON
提出前の終了を差し止めできるできない Agent Stop では止められないできない Stop で処理を続けさせることはできない
結果に文脈を足すできる一部 終了コード 0 なら標準出力がAIの文脈に入る一部 同左

Kiro では、フックの代わりに次の2つで同じ効果を得ます。

  • 記録のない提出は不合格にする。 pms submit は、提出された連番が pms act の記録にあるかを確かめます。playwright-cli を直接呼んだ操作は記録に残らないため、その提出は不合格になります。
  • 終わったかどうかは進行役が決める。 スクリプト実行(docs/94 の B2)では、進行役がカードごとにセッションを起こして結果を確かめます。AIが途中で終わっても、同じカードをもう一度出すだけで済みます。Stop のフックは要りません。

7. フックを使えない場合

フックは、AIの外からIDEが割り込む仕組みです。フックを使えない環境(組織の設定で止められている、Kiro の IDE など)では、AIがどうしても通る場所に同じ働きを埋め込みます。その場所は3つあります。pms のコマンドの出力、提出の検査、タスクキューです。

7-2. 記録の抜けを止める(PreToolUse の代わり)

フックがあれば、直接呼びは実行の前に止まります。フックがなければ、直接呼びは失敗するか、記録を残さずに実行されます。どちらの場合も、提出の時点で必ず止まります。

② 提出の検査が返す内容(不合格のとき)
{
  "result": "rejected",
  "card": "C-0412",
  "errors": [
    "連番5 は pms act の記録にない"
  ],
  "hint": "画面操作は pms act で行い、その連番を書く",
  "next": "pms submit --card C-0412"
}
④ pms act の出力(毎回、末尾に現在地を載せる)
{
  "ok": true, "seq": 7,
  "locator": "getByRole('button', { name: '登録' })",
  "locator_class": "stable",
  "now":  "カード C-0412: 状態 S-PRINTER-REGISTERED を作る",
  "next": "状態ができたら pms submit --card C-0412"
}

④は PostToolUse と SessionStart の代わりです。AIは道具を使うたびに、自分の出力ではなく道具の出力から現在地を受け取ります。会話が要約されても、次の操作の結果に現在地が載るため、そこで元の作業に戻れます。

7-3. 途中で終わったときに続ける(Stop の代わり)

フックがなければ、サブエージェントが提出せずに終わるのを止められません。そこで、終わったあとに進行役が気づいて、同じカードをもう一度出します。

7-4. ループをプログラムに持たせる(スクリプト実行)

docs/94 の実行形態 B2 では、カードを順に回すループそのものをプログラム(pms run)が持ちます。AIはループの1回分だけを行うので、途中で終わってもループは止まりません。Stop のフックが要らなくなります。

7-5. フックありとフックなしの比較

観点フックあり(VS Code + Copilot)フックなし・IDE 内(B1)フックなし・スクリプト(B2)
記録の正しさ担保される pms submit の検査担保される 同じ検査担保される 同じ検査
直接呼びに気づく時点実行の直前(PreToolUse)提出のとき。PATH に置かなければ実行のときにも失敗する実行の直前(使用禁止の設定)
提出せずに終わったときその場で続けさせる(SubagentStop)次の pms next で同じカードが出る。入口が止まったら利用者が「続けて」と伝えるループが同じカードを出し直す。人手は要らない
要約の後に作業へ戻るPostToolUse と ④ の両方④(道具の出力の現在地)カードごとに会話を捨てるため、要約がほぼ起きない
やり直しの手間少ない直接呼んだ分が増える少ない
使える環境VS Code + Copilot(フックが許可されていること)Copilot・Kiro の IDE のどちらでもCopilot CLI・Kiro CLI(端末から実行)

まとめ。フックがあってもなくても、記録の正しさは変わりません。正しさは pms act(記録を道具が書く)と pms submit(提出のたびに検査する)が担保しているためです。フックがない場合に変わるのは、気づくのが遅れる分のやり直しの手間と、IDE 内では入口が止まったときに「続けて」と伝える手間だけです。この手間もなくしたい場合は、ループをプログラムに持たせる B2 を使います。
