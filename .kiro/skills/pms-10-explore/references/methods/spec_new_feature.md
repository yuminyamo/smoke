# 方式: spec_new_feature

方式名: 新機能の仕様書起点

本ファイルはシナリオ策定方式の1つである(00 ■シナリオ策定方式)。`stages.md` §10 パートBの共通契約(スコープ・妥当性基準・記載ルール・既存テストスクリプトの扱い)は全方式に適用され、本ファイルはそれを緩めない。本ファイルが定めるのは、シナリオ候補をどこから、どう抽出するかだけである。

## 1. 入力資料

| 資料 | 所在 | 扱い |
|---|---|---|
| 新機能の仕様書 | 領域指示が示すもの(要件定義・機能仕様・画面仕様など) | 主たる入力。新しく実装した機能・変更した機能の基本動作を読む |
| 利用者マニュアル | 領域指示、または KB T11 | 既存機能とのつながり(到達経路・前提の操作)を補う。新機能が未記載でもよい |
| 実画面 | 検証環境 | 新機能が配備されていることの確かめと、仕様書にない操作の確かめ(根拠 `画面観察`) |

- **前提条件: 対象の機能が検証環境に配備済みであること。** シナリオ生成と探索は、現行どおり連続して行う(作業10を分けない)
  - 入口 skill がフロー開始時に利用者へ確かめる(未配備なら、フローを始めない)
  - 作業10は、工程0のあと・パートBの前に、仕様書が示す新機能の画面または機能に到達できることを実画面で確かめる。到達できなければシナリオを作らず、flow.md のメモ欄に「方式の前提条件を満たさない(新機能が未配備)」と確かめた内容を書いて止まる(status.yaml は出力しない)。配備されたら、工程0の復元からやり直す
- **機能一覧の確定元**(初回フローの A2): マニュアルの目次構造。新機能がどの機能に属するかは仕様書から決め、既存の機能一覧にない機能なら追加採番する

## 2. 候補の抽出手順

1. 仕様書から、新しく実装した、または変更した**利用者の作業**を列挙する。内部処理・非機能要件・管理者向けの設定値の網羅は候補にしない(ステップ1の範囲外は申し送り台帳へ)
2. 各作業について、仕様書が定める正常系の完了条件(何ができれば成功か)を確かめる。完了条件が仕様書から読み取れない作業は、報告書 §6 に書き、`推測(仕様未記載)` を根拠にするか候補から外す
3. 新機能の操作が既存機能の操作を前提にする場合(例: 既存の画面から新しいボタンで到達する)、前提部分は既存のシナリオ部品・fixture の流用を第一選択とし、シナリオのステップは新機能の検証意図から始める。前提状態が `vocab.initial_state_set` で表せなければ、シナリオを作らず申し送り台帳へ記録する(共通契約の記載ルール8)
4. 候補を共通契約の妥当性基準と選定指針で選び、1機能あたり `vocab.default.scenarios_per_feature` 本に絞る。落とした候補は申し送り台帳に記録する
5. 残した候補を検証意図ごとのステップ(3〜6)に分け、ステップごとに仕様書の章・項番を根拠として特定する

## 3. 根拠の書き方

- 文書名+章番号(例: `機能仕様書 一括印刷 v1.0 3.2`)。仕様書の版を文書名に含める(新機能の仕様書は改訂が続くため)
- 文書に記載がない: `推測(仕様未記載)` / `画面観察`

## 4. 代表値と範囲外の扱い

- パラメータの代表値は、仕様書の既定値、または仕様書の例の最初の値を1つ選ぶ
- 仕様書にある入力検証・エラー表示・境界値・権限の違いは候補に入れず、申し送り台帳へ記録する(新機能は異常系の記載が多いが、ステップ1の範囲は変わらない)
- 新機能に合わせて既存機能の挙動が変わる場合、その既存機能の既存シナリオは変更しない。変化は探索で実挙動として記録し、既存シナリオへの影響は報告書 §6 に書く

## 5. 方式固有の禁止事項

- 新機能が検証環境で確かめられないまま、仕様書だけでシナリオを確定しない(前提条件を満たさないときはシナリオを作らない)
- 仕様書の記載を理由に、既存の scenarios.md の行(期待結果・判定基準)を変更しない(共通契約・既存行は変更しない)

## 6. 方式固有のDoD

- [ ] パートBの前に、新機能の画面または機能に実画面で到達できることを確かめ、flow.md のメモ欄に確かめた内容を書いた
- [ ] 全シナリオで、少なくとも1つのステップの根拠が新機能の仕様書(版を含む文書名+章番号)である
- [ ] 仕様書にあるステップ1の範囲外の確認(入力検証・エラー・境界値・権限など)を申し送り台帳に記録した

## 7. 方式固有のKB・DISC

- KB: 新機能の仕様書の所在(版を含む)を KB T11 に登録する。新しい画面は T01、到達経路は T02 に、探索で確かめたあとに反映する
- DISC: 仕様書と実挙動の食い違いは種別 `実画面≠仕様書`。マニュアルにも記載があり食い違えば `三者不一致`(00 ■不整合レポート)
