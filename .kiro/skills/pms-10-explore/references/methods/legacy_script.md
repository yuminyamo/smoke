# 方式: legacy_script

方式名: 既存テストスクリプト起点

本ファイルはシナリオ策定方式の1つである(00 ■シナリオ策定方式)。`stages.md` §10 パートBの共通契約(スコープ・妥当性基準・記載ルール・既存テストスクリプトの扱い)は全方式に適用され、本ファイルはそれを緩めない。本ファイルが定めるのは、シナリオ候補をどこから、どう抽出するかだけである。

## 1. 入力資料

| 資料 | 所在 | 扱い |
|---|---|---|
| 既存テストスクリプト | 領域指示が示すもの、または KB T11 に所在があるもの(手動テストの手順書・過去の自動テストコードなど) | 主たる入力。**参考情報であり、正解の根拠でも操作手順の正本でもない**(00 ■オラクル(正解の定義)の原則・共通契約の「既存テストスクリプトの扱い」) |
| 利用者マニュアル・仕様書 | 領域指示、または KB T11 | スクリプトから拾った候補の裏付け。記載があれば根拠として先に書く |
| 実画面 | 検証環境 | 文書にもスクリプトにも記載がない操作の確かめ(根拠 `画面観察`) |

- **前提条件**: 対象のスクリプトの所在が分かること(領域指示または KB T11)。所在が分からなければ、パートBに入る前に人間に1回だけ確かめる。所在が示されないときは、flow.md のメモ欄にその旨を書いて止まる(シナリオを作らない)
- **機能一覧の確定元**(初回フローの A2): マニュアルの目次構造(スクリプトの分類は機能の単位と一致するとは限らないため)。マニュアルがなければスクリプトの分類を使い、その旨を報告書 §6 に書く

## 2. 候補の抽出手順

1. スクリプトを読み、テストケースの単位(シート・番号・テスト関数など)ごとに、**利用者が何をして、何を確かめているか**を1行で書き出す(操作手順は書き出さない)
2. 書き出した行を、利用者の一連の作業ごとにまとめる。1機能の中で完結する一連の作業を1候補とする。機能をまたぐ連鎖は連結シナリオの対象として申し送り台帳へ記録する
3. 各候補をステップ1の範囲で切り出す。スクリプトにある異常系・境界値・値のバリエーション・権限外操作は候補に入れず、申し送り台帳へ記録する(共通契約。**スクリプトにあることを理由にスコープを広げない**)
4. 候補を共通契約の妥当性基準と選定指針で選び、1機能あたり `vocab.default.scenarios_per_feature` 本に絞る。落とした候補は申し送り台帳に記録する
5. 残した候補を検証意図ごとのステップ(3〜6)に分ける。期待結果は、スクリプトの記載を写さず業務的な意味で書き直す。マニュアル・仕様書に同じ内容の記載があれば、その章番号を根拠として先に書く

## 3. 根拠の書き方

- `既存テスト:<スクリプト名>#<該当箇所>`(例: `既存テスト:印刷_回帰テスト手順書.xlsx#印刷!No.3`)
- 文書に記載があれば、文書名+章番号を先に書く(例: `利用者マニュアル4-2 / 既存テスト:印刷_回帰テスト手順書.xlsx#印刷!No.3`)
- どちらにも記載がない: `推測(仕様未記載)` / `画面観察`

## 4. 代表値と範囲外の扱い

- パラメータの代表値は、スクリプトで最も多く使われている値、またはスクリプトの最初のケースの値を1つ選ぶ。選んだ理由を報告書 §6 に1行で書く
- スクリプトにある同一経路のバリエーションは代表1件に畳み、残りを申し送り台帳(`同一経路`)へ記録する
- スクリプトにある範囲外の確認は、スクリプト名と該当箇所を添えて申し送り台帳へ記録する(後のステップ2・3で拾えるようにするため)

## 5. 方式固有の禁止事項

- スクリプトの操作手順・画面の文言・期待値を scenarios.md に書き写さない(共通契約の記載ルール2・4)
- スクリプトに書かれた接続先・アカウント・パスワードの値を使わない(環境情報のキーで扱う。00 ■検証環境の情報)
- スクリプトとマニュアル・仕様書が食い違うとき、どちらかを正しいと決めてシナリオを書かない。期待結果は業務的な意味で書き、パートCで実挙動を確かめて DISC に記録する

## 6. 方式固有のDoD

- [ ] 全シナリオで、少なくとも1つのステップの根拠が `既存テスト:<スクリプト名>#<該当箇所>` である
- [ ] 読んだスクリプトのテストケースのうち、シナリオに入れなかったもの(範囲外・同一経路・選定で落としたもの)を、スクリプト名と該当箇所を添えて申し送り台帳に記録した
- [ ] 代表値を選んだ理由を報告書 §6 に書いた

## 7. 方式固有のKB・DISC

- KB: 読んだスクリプトの所在を KB T11 に登録する(内容は転記しない)
- DISC: スクリプトの記載と実挙動の食い違いは種別 `実画面≠既存テスト`。文書とも食い違えば `三者不一致`(00 ■不整合レポート)
